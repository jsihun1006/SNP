# 로컬 실측과 실행시간 추정

2026-11-18 Apple M5 MacBook Air, 메모리 16GB에서 측정했다. PyTorch 2.8.0, CPU 4스레드다.

## 측정값

| 조건 | 업데이트당 창 | 실제 한 번에 처리 | 중앙값 | 검증 전체 |
|---|---:|---:|---:|---:|
| CPU | 32 | 8 | 3.64초 | 17.29초 |
| M5 GPU | 64 | 32 | 2.45초 | 6.97초 |

GPU 업데이트 시간은 준비 배치 1회를 제외한 3회 측정이다. 검증은 J03WQQ의 실제 815개 창을 전부 추론하고 디코딩·채점한 값이다.
프로세스 최고 RSS는 약 3.58GB였다. 별도 GPU 메모리 최고치와 전체 시스템 사용량을 뜻하지 않는다.

원본 로컬 XML의 6경기 좌표 캐시 생성은 약 4분 30초였다. 기존 예측 D와 5fps 추론 생성은 경기당 19.7~28.8초, 6경기 약 140초였다. 이후 캐시 재사용과 25fps 특징·창 생성은 약 5.5초였다.

## 현재 구성

- 경합 후보 창 11,054개, 일반 창 pool 16,325개다.
- 경합 후보를 한 바퀴 돌고 일반 창을 보충하면 epoch당 14,739창이다.
- 배치 64 기준 epoch당 업데이트 231회다.
- 검증에서 고른 후보는 인플레이의 38.80%이며 실제 H/A 전환 302개 중 267개를 포함한다. 이 수치는 검증으로 고른 후보의 포착률이며 테스트 성능은 아직 측정 전이다.

## 학습 예산별 추정

| epoch당 창 | 업데이트 | epoch당 | 40 epoch 상한 |
|---|---:|---:|---:|
| 2,000 | 32 | 1.42분 | 57분 |
| 4,000 | 63 | 2.69분 | 108분 |
| 8,000 | 125 | 5.22분 | 209분 |
| 14,739 | 231 | 9.55분 | 382분 |

위 수치는 짧은 실측을 곱한 추정이다. 장시간 발열·체크포인트 저장·첫 GPU 초기화는 추가될 수 있다. 본 학습 중 첫 epoch 실측으로 갱신한다. 40 epoch 전에 얼리 스토핑되면 그만큼 줄어든다.

빠른 첫 실행 후보는 epoch당 2,000창이다. 경합 1,500창과 일반 500창을 매 epoch 다시 뽑는다. 기존 전체 창 예산은 파라미터 원장에서 유지하며 사용자의 예산 선택 후 변경한다.

## 오류와 수정

- 첫 MPS 시도는 expanded attention query의 Metal buffer assertion으로 중단됐다. attention query를 contiguous 메모리로 만든 뒤 학습·추론을 통과했다.
- 64창을 물리 배치로 한 번에 계산한 시도는 첫 배치가 장시간 정체돼 중단했다. 로그는 data/transition_final/mps_batch64.log다.
- 실제 배치 32를 두 번 계산한 뒤 Adam을 한 번 실행해 업데이트당 64창을 유지한다. 원래 32창보다 전체 창을 처리하는 총 계산은 크게 줄지 않았다.
- CPU 32창 한 업데이트와 검증·저장 확인을 통과했다. MPS 64창 누적 조건에서도 한 업데이트·검증·저장과 완료 epoch 재개 확인을 통과했다.

## Colab T4 실측

2026-11-18 GPU에서 실배치 64로 측정했다. 워밍업 제외 업데이트 1.259·1.264·1.284초, 검증 전체 4.500초, GPU 메모리 최고 약 10.95GB였다. 전체 14,739창은 epoch당 231스텝이며 약 4분 56초, 최대 40 epoch는 약 3시간 18분으로 추정한다. epoch당 2,000창이면 같은 모델로 약 30분이다. 실제 장기 학습 시간은 첫 epoch에서 다시 기록한다.
