# DFL 경합 전환 재판정 실험계획

작성일은 2026-11-18이다. 설정 원장은 parameters.csv다.

## 목적과 비교

고정된 5fps PathCRF와 5fps + 25fps 경합 재판정을 같은 DFL 경기, 같은 볼 관측, 같은 데드볼 마스크에서 비교한다. 주 지표는 주최측 evaluation/possession_metrics.py의 temporal IoU 0.3·0.4·0.5·0.6·0.7 평균 Spell F1이다. 방향별 가짜·누락 전환, 1초 이내 매칭 전환의 평균 절대 시점 오차와 2초 미만 점유 재현율도 저장한다.

예측 D를 주 조건으로 쓰고, 정답 D를 넣은 진단 조건을 함께 출력한다. 진단 조건의 인플레이 경계와 5fps 추론은 별도로 생성한다. H/A 주 지표는 DFL 정답 D로 평가 대상 구간을 정의하므로 실제 사용과의 차이를 함께 확인한다. 예측 D가 실제 점유를 지우면 누락으로 반영한다. 순수 H↔A 전환 수에서는 H↔D와 A↔D를 제외한다.

## 데이터 분할

| 용도 | 경기 |
|---|---|
| 학습 | J03WMX, J03WN1, J03WOH, J03WOY, J03WPY |
| 검증 | J03WQQ |
| 테스트 | J03WR9 |

같은 경기의 전후반은 같은 용도로 사용한다. 창은 하프와 데드볼 경계를 넘지 않는다. 테스트는 모델과 설정 고정 후 test 단계에서 읽는다. 이번 비교는 한 경기 홀드아웃이며, 7폴드 확대는 시간을 본 뒤 결정한다.

기본 PathCRF는 공식 trial 140 체크포인트다. commit은 1b7c6f85a6b78c92e4543fde72ca2b86a933f997이다. 예측 D는 기본 구현에서 scene_two_models_v1/full/best.pt를 선택했다. 해당 모델과 PathCRF의 학습·검증·테스트 분할이 일치하는지 실행 전에 검사한다. 보유 dead-ball 모델이 별도의 모델이면 그 출력 연결은 아직 필요하다.

## 입력

- 105×68m 표준 피치에서 선수·볼 좌표와 축 방향을 일치시킨다. 모델 위치 입력도 m 단위를 유지한다.
- 모든 프레임의 경기 ID, 하프, 원본 frame_id와 timestamp를 추적한다.
- 팀은 H/A로 표시한다. 수비 방향과 바깥 노드 입력은 제외한다.
- 골키퍼 표시는 메타데이터에서 역할을 확인할 수 있는 트랙에 사용한다. 미확인 역할은 별도 known 마스크로 표현한다.
- 선수는 x, y, vx, vy, 속력과 가속도 크기를 사용한다. 관측·속도·가속도 마스크를 추가한다.
- 선수 속도는 15프레임, 가속도는 9프레임의 2차 Savitzky–Golay 필터로 평활화한다. 짧은 연속 관측 구간은 차분값을 쓰고 재등장 첫 속도는 무효 처리한다.
- 볼은 x, y, vx, vy와 위치·속도 마스크를 사용한다. 모델 입력 토큰의 player-only 속력·가속도 채널은 볼에서 0이다.
- 25fps에서 직접 속도를 계산하며 결측·하프·데드볼·원본 프레임 불연속을 건너뛰지 않는다.
- 학습 볼 결측은 자연 결측을 포함한 9.5%를 목표로 한다. 9~10%는 사용자가 다른 컴퓨터에서 얻은 추정 범위다. 추가 가림은 5~25프레임 연속 구간 균등 분포라는 시뮬레이션 가정이다.
- 고정 seed 100으로 하프별 가림을 한 번 생성하고 창마다 재사용한다. 선형 보간 대체는 적용하지 않는다.
- 검증·테스트는 원래 관측 볼을 사용한다. 같은 체크포인트에서 볼을 가린 추가 추론을 진단으로 수행한다.
- 좌우·상하 뒤집기는 선수·볼을 함께 변환한다. 해당 속도축의 부호도 바꾸고 H/A 라벨은 유지한다.

## 후보 선택

5fps가 불확실한 구간과 선수 움직임의 경합 후보를 합친다.

- 불확실성은 공개 PathCRF의 coarse 송신 선수 확률을 H/A로 합한 두 팀 질량의 차이로 계산한다.
- 선수 움직임은 예측한 점유 가능 선수와 가장 가까운 상대 선수의 거리와 0.2초 동안의 접근량을 사용한다.
- 공이 가까워도 팀 점유가 유지되는 사례를 학습에 포함한다.
- 5fps 예측 전환점도 후보에 포함한다. 후보 신호 전후 15프레임은 구현 기본값이다.
- 검증에서 기준값 조합을 탐색한다. 후보 합집합이 예측 인플레이의 40% 이내인 조합 중 실제 전환을 가장 많이 포함하는 조합을 고른다. 동률에서는 후보 프레임 수가 적은 조합을 쓴다.
- 검증에서 고른 조합을 고정해 학습과 테스트에도 쓴다. 테스트의 후보 비율은 별도로 보고한다.
- 학습 경기의 5fps 후보는 학습에 사용된 고정 PathCRF의 추론이다. 이번 단일 분할 실험에서 학습 후보를 OOF로 만들지는 않는다.

## 25fps 모델과 디코딩

4초 100시점 창을 사용한다. 학습 창 간격은 0.5초다. 25fps에서 12·13프레임씩 번갈아 옮긴다. 추론 창 간격은 1초다. 짧은 구간도 포함하고 attention과 모든 손실에서 패딩을 제외한다.

128차원, 4헤드의 공간·시간 블록을 두 번 쌓는다. 각 블록은 같은 팀끼리 공유하는 induced attention, 전체 선수·볼 induced attention, 양방향 시간 Transformer 2층으로 구성된다. 유도점 수 16, FFN 256은 구현 기본값이다. 원본 PathCRF의 구조 원리를 가져왔으며, 동일 가중치나 완전히 동일한 backbone으로 취급하지 않는다.

팀별 선수 표현을 학습한 attention 가중치로 합친다. 볼 표현과 합쳐 프레임별 H/A 2개 점수와 유지·H→A·A→H 3개 점수를 낸다. 연속 두 시점 표현으로 전환 점수를 계산한다. 경합 창의 겹치는 점수는 중심부 비중을 높여 합친다.

경합 후보 구간의 양옆 5fps 팀 라벨은 고정된 연결점으로 쓰고 2상태 Viterbi를 수행한다. 원래 5fps 결과는 후보 밖에서 그대로 유지한다. 인플레이 시작점에는 이전 데드볼 앞 팀을 연결하지 않는다. A A D D H H에서 A→H를 인플레이 전환으로 세지 않는다.

## 학습과 재개

전체 가중치는 새로 초기화한다. H/A CE, 전환 CE, 2상태 CRF 음의 로그우도를 1:1:1로 더한다. CE는 유효 표본 평균, CRF는 유효 시점 수로 나눈다. 팀 라벨이 없는 구간은 CE에서 제외하고 CRF 연쇄도 끊는다. 유지 대비 드문 전환은 학습 빈도 역제곱근, 최대 8배의 가중치를 준다. 가중치 상한은 구현 기본값이다.

경합 후보 창을 한 바퀴 돌고 일반 인플레이 창을 보충해 3:1로 맞춘다. 매 epoch 창 순서를 seed로 섞는다. 창 내부 시간 순서는 유지한다. 일반 창이 부족할 때만 복원추출한다. epoch-window-cap을 지정하면 경합 창은 무복원 부분 추출하고 일반 창을 보충한다.

Adam 초기 lr 1e-3, weight decay 1e-4, dropout 0.1을 쓴다. 사용자의 최신 요청으로 유효 배치를 64로 확대했다. 실제 마이크로배치는 장치 실측으로 정한다. 매 epoch 최종 검증 Spell F1을 계산한다. 3회 연속 개선이 없으면 lr을 절반으로 낮추며 하한은 1e-5다. 5회 연속 개선이 없으면 멈춘다. 최대 40 epoch와 epoch당 창 수는 시간에 따라 조정할 잠정값이다.

best.pt와 last.pt를 원자적으로 저장한다. last에는 Adam 상태와 CPU·장치 난수 상태를 포함한다. 같은 명령을 다시 실행하면 마지막 완료 epoch에서 이어진다. 가중치만 파일에 남는 것과 학습 상태 전체 재개를 구분한다.

## 실행 순서

1. benchmark에서 로컬 자료·체크포인트·분할·프레임과 시간 정렬을 확인한다.
2. 원본 tracking 캐시와 고정 예측 D·5fps 출력 캐시를 만든다.
3. 검증에서 경합 기준값을 고정하고 실제 학습·추론 창 수를 센다.
4. 학습·추론 한 배치 워밍업을 제외하고 여러 배치를 실측한다.
5. 전체 검증 추론을 실측하고 시간표를 저장한다.
6. 사용자가 학습 예산을 결정하면 train을 실행한다.
7. 모델을 고정한 뒤 test에서 예측 D와 정답 D 조건을 평가한다.
8. holdout.json과 원본 프레임 정렬 Parquet를 저장하면 해당 실험을 종료한다.

## 확인된 구현 검증

CPU에서 DFL 학습 창 32개를 쓰는 1 epoch 사전 실행, 전체 검증, best·last 저장을 통과했다. 이 점수는 학습 파이프라인 검사이며 모델 성능 보고에 사용하지 않는다. verify.py에서 총당 2상태 경로 점수와 CRF 손실, 결측 라벨 구간, 양옆 경계 Viterbi와 패딩을 확인한다.
