# DFL TranSPORTmer dead-ball experiments

The four conditions combine observed or restored ball coordinates with no event inputs or training-only event labels. All use the seven half-level folds in `experiments/deadball/lightgbm/dfl_7fold/dfl_half_7fold.json`.

Use Windows x64, Python 3.10.22 and an NVIDIA CUDA device. The experiment used an RTX 5080 with PyTorch 2.8.0 and CUDA 12.8.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r experiments/deadball/transportmer/dfl_7fold/requirements-lock.txt
git lfs pull
.\.venv\Scripts\python.exe src/deadball/export_deadball_inputs.py --dfl-cache data/external/dfl/repro_cache --atd-root data/merged --output data/model_inputs --vif-report data/lightgbm_input_vif.json
.\.venv\Scripts\python.exe src/deadball/compare_transportmer_folds.py --splits experiments/deadball/lightgbm/dfl_7fold/dfl_half_7fold.json --cache data/external/dfl/repro_cache --output data/transportmer_reproduction --epochs 25 --patience 4 --batch 24 --stride 240 --learning-rate 0.0002 --motion-input
```

The input exporter builds the DFL training trajectories and the competition ATD input from their original sources. The experiments use DFL only. Test player dropout is generated by the experiment using the shared simulator. Both ball conditions start with the same simulated contiguous gaps, with a 40.7% target missing share and a 6 s mean gap length.

The model uses 128 embedding dimensions, 16 attention heads and a 512-wide FFN. Windows contain 60 samples at 6.25 Hz. The motion input centers the pitch coordinates and adds consecutive coordinate differences with a validity mask. The ball restorer uses learning rate 0.001; the dead-ball classifier uses 0.0002. Each fold picks the epoch count using one of its 12 training halves and refits on all 12 halves. When tuning a restored-ball classifier, its validation input comes from the inner-training ball restorer.

Scoring saves pre- and post-correction dead-ball and in-play spellF1 for each half, each fold and the full experiment. The six correction rules are shared with the LightGBM experiment. A restored crossing with insufficient corroboration lowers the Viterbi entry cost. Only observed crossings or corroborated restored crossings can force a line-out.

The output directory can be reused to resume completed folds with the same manifest. Per-frame probabilities and decisions are saved locally under `predictions/`. The reference directory contains the aggregate results and settings from the reported run. GPU and library differences can affect the training trajectory.


## Reference results

**TranSPORTmer Model 1** uses the restored-ball condition with no event inputs and all six correction rules. Its reference dead-ball Spell F1 is 0.909692 across the seven half-level folds.

| Ball inputs | Event inputs | Dead-ball before / after | In-play before / after |
|---|---|---:|---:|
| Observed | None | 0.690444 / 0.819015 | 0.685486 / 0.797552 |
| Observed | Training only | 0.513564 / 0.756465 | 0.512077 / 0.690830 |
| Restored gaps | None | 0.753566 / 0.909692 | 0.736304 / 0.884757 |
| Restored gaps | Training only | 0.749231 / 0.906434 | 0.727328 / 0.888640 |

Six observed-ball half predictions were constant before correction, two without events and four with training-only events. The four conditions use simulated ball gaps. The previous LightGBM experiment used original DFL ball traces for its correction rules. Both experiments use half-level splits that can place the other half of the same match in training.

## Model 1 missed stoppages

Pass the reference run's `predictions` directory or a CSV containing `match_id`, `frame_id`, and the final binary `dead` prediction. The directory can contain per-half `*_restored_none.npz` or `*_restored_none.csv` outputs. The audit checks each half against its stored Spell F1 and writes the per-spell details and situation counts. It uses DFL events near each stoppage to identify the restart type and, where recorded, the stoppage cause.

```sh
python src/deadball/audit_transportmer_deadball_misses.py --predictions data/transportmer_reproduction/predictions --output data/transportmer_model1_misses
```

## Rerun Model 1 with frame CSVs

The Model 1 option runs the restored-ball, no-event condition on the original split and writes one CSV per evaluation half. Use `--prepare-dfl` with the seven local DFL Parquet matches to generate the simulated training cache.

```sh
python src/deadball/compare_transportmer_folds.py --model-1 --prepare-dfl --motion-input --splits experiments/deadball/lightgbm/dfl_7fold/dfl_half_7fold.json --cache data/external/dfl --inputs data/transportmer_model1_rerun/inputs --output data/transportmer_model1_rerun
python src/deadball/audit_transportmer_deadball_misses.py --predictions data/transportmer_model1_rerun/predictions --reference data/transportmer_model1_rerun/by_half.csv --output data/transportmer_model1_rerun/missed_stoppages
```

The original run used CUDA. Choose `--device mps` for a Mac rerun. A rerun can produce different predictions, so the audit reads the scores from the same run as the prediction file.

For the single-match evaluation, replace `--splits ...` with `--holdout J03WR9 --validation-match J03WQQ` and use a new output folder. Epoch selection holds back J03WQQ within the training pool. Both stages refit on all six training matches before predicting both J03WR9 halves. Add `--holdout J03WR9` to the audit command.

For the exploratory single-match run, use `--holdout J03WR9 --train-loss-only --ball-weights <six-match checkpoint>` with `--epochs 8 --patience 3`. The classifier trains once on all six matches and selects the lowest training BCE. The ball checkpoint's adjacent manifest must identify the same six training matches and holdout. The Mac run uses `--microbatch 8` to accumulate each logical batch of 24.
