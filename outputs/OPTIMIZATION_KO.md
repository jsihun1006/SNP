# 처리 속도 점검 결과

2026-11-15 오전, RTX 5080에서 원본 영상 네 지점의 32프레임을 고정해 예열 후 반복 측정했습니다. 모델, FP32, 입력 크기, 프레임 처리 범위, 타일 겹침, 임계값은 유지했습니다.

| 전체/확대/타일 배치 | 속도 | 결과 비교 |
|---|---:|---|
| 1/4/8 (기본) | 6.79fps | 기준 |
| 4/8/32 | 6.57fps | 좌표·신뢰도·ROI 차이 발생 |
| 8/16/32 | 6.49fps | 좌표·신뢰도·ROI 차이 발생 |

큰 배치에서는 GPU 전체 메모리 사용량이 약 11.2~14.2GB까지 증가했지만 속도 이득은 없었습니다. 더 큰 배치 시험은 메모리 사용량이 약 15.8/16.3GB에 도달해 중단했습니다. 기본 GPU 메모리 사용량은 약 3.4GB입니다.

추가 시험에서는 CPU 스레드 1/2/4와 cuDNN 자동 튜닝을 비교했습니다. 기본 6.779fps 대비 최고 6.800fps로 약 0.3% 차이였고, 반복 시간의 변동을 고려하면 유의미한 개선으로 보지 않았습니다. 타일 배치 16도 약 0.6% 차이에 그쳤고, 원본 검출 관측값이 달라져 적용하지 않았습니다.

기본 설정의 반복 결과는 시간 측정 필드를 제외하고 동일했습니다. 비교에는 최종 후보뿐 아니라 전체/확대/타일 관측, ROI 중심·창 좌표, 원본 관측 기록을 포함했습니다. 이 표본 비교는 경기 전체의 정답 정확도를 검증한 결과는 아닙니다.

25개 실작업 청크의 저장 시각과 검출 시간을 비교한 결과, 검출 외의 모든 작업(영상 읽기, JSON, 체크포인트 저장, 상태 기록 등)은 약 2.77%였습니다. 입출력 최적화로 얻을 수 있는 이득도 작아 체크포인트 보존과 온도 제어를 유지했습니다.

따라서 검증된 기본 배치 1/4/8, 청크 32로 기존 전반 결과 폴더를 재개했습니다. 기존 완료 832프레임을 보존했으며 모델·해상도·정밀도·탐지 범위는 변경하지 않았습니다. 재개 로그는 `pc1.resume.stdout.log`, `pc1.resume.stderr.log`입니다.

상세 측정값: `batch-benchmark.json`, `runtime-benchmark.json`.
