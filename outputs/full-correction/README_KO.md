- 카메라 이동 추정 실패와 실제 컷 전환을 구분합니다.
- 관측 후보의 시간적 연결과 경쟁 후보의 차이를 함께 평가합니다. 약한 후보도 앞뒤 관측이나 참고 자료의 지지가 있으면 고려합니다.

- Homography나 탐색 기준점이 없고 기존 후보도 없는 프레임은 전체 화면 입력 1536, 배치 1로 다시 탐색합니다.
- 자동 선택, 검토 후보, 미확정을 분리하며 관측 사이 좌표를 보간하지 않습니다.

이는 공을 찾을 기회를 늘리는 실행 설정이지 정답률 100%를 보장하는 설정이 아닙니다. 낮은 임계값에서 추가된 후보에는 오검출이 섞일 수 있어 검토 후보도 함께 보존합니다. 원본 후보와 영상·모델 파일은 변경하지 않습니다.

## 저장 위치와 상태

작업 폴더: `H:\data\ball-tracking-results\first_half\correction_recall_v1`

- `progress.json`: 전체 진행률과 처리 속도, 남은 시간 추정.
- `recovery_progress.json`: 현재 청크의 추가 탐색 진행률.
- `chunks`: 재개 가능한 청크별 후보·선택 기록과 체크섬.
- `corrected_ball_coordinates.csv`: 완료 시 생성되는 전반 전체 좌표·상태.
- `frame_decisions.jsonl.gz`: 완료 시 생성되는 원본·추가 후보와 판단 근거.
- `job_complete.json`: 완료 상태와 결과 체크섬.

`Check-Progress.ps1`로 현황을 확인할 수 있습니다. `Stop-Correction.ps1`은 현재 청크가 저장된 뒤 중단하도록 요청합니다. 재개는 STOP 파일을 제거하고 같은 코드·입력·설정·출력 경로로 실행해야 합니다. 입력이나 코드가 바뀐 체크포인트는 섞지 않습니다.

경기장 좌표가 있는 경우에도 지면에 투영한 값입니다. 공중볼의 실제 3D 위치나 보이지 않는 공의 실제 위치를 복원한 것으로 해석하면 안 됩니다. 자동 관측 선택률은 정밀도/재현율이 아니며, 정확도 향상은 별도 정답 검증이 필요합니다.

## 최종 검증 단계

위 작업 폴더는 자동 처리의 원본 기록으로 보존합니다. 최종 좌표는 이 문서와 같은 폴더의 `corrected_ball_coordinates.csv`에 따로 저장하며, 자동 기록을 덮어쓰지 않습니다.

표본 검수에서 손·유니폼 로고·광고 무늬가 신뢰도 0.8 이상에서도 잘못 선택된 사례가 있었습니다. 따라서 경기장 변환이 없으면서 모델 신뢰도가 0.60 미만이거나 중심 작은 패치의 녹색 비율이 0.25 미만인 자동 선택은 검토 후보로 돌립니다. 이는 증거 부족을 다루는 보수적인 절차이지, 해당 관측이 전부 가짜 공이라는 분류 규칙은 아닙니다. 큰 흰 공의 중심도 녹색이 아닐 수 있으므로 실제 공이 검토에 포함될 수 있습니다. 모든 후보와 임시 좌표는 보존하며, 정확한 프레임을 직접 확인한 공 관측은 이 규칙 이후에 별도로 반영합니다.

총 45프레임의 명시적 시각 검수 내역(기존 검출점 20개 재선택·유지, 25개 검토 전환)을 준비했습니다. 이 수치는 전체 79,467프레임의 정답 검증 수나 정확도 측정값이 아닙니다. 추가 후보의 수, 자동 선택률, 검토로 전환한 수를 미탐·오탐 개선율로 해석해서는 안 됩니다.

최종 CSV에서 `pixel_x`, `pixel_y`는 선택한 관측의 원본 1920×1080 영상 좌표입니다. `provisional_pixel_x`, `provisional_pixel_y`는 확정된 공 좌표가 아닌 검토용 위치입니다. `needs_review=True`인 행은 선택 상태여도 추가 확인이 필요합니다. `review_intervals.csv`는 이런 구간을 찾기 위한 목록입니다.
